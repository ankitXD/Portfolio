# Next.js Migration Plan — Portfolio

> **Target version: Next.js 16.2.6** (`npm i next@latest` or `npm i next@16.2.6`)
>
> Official reference: [Migrating from Vite](https://nextjs.org/docs/app/guides/migrating/from-vite) | [Tailwind CSS v3 with Next.js 16](https://nextjs.org/docs/app/guides/tailwind-v3-css)

---

## Current Stack → Target Stack

| Current                 | Target                                             |
| ----------------------- | -------------------------------------------------- |
| React 19 + Vite 6       | **Next.js 16.2.6** (App Router + Turbopack)        |
| react-router-dom v7     | Next.js file-based routing                         |
| Tailwind CSS 3          | Tailwind CSS 3 (keep — Next.js 16 has a v3 guide)  |
| Framer Motion           | Framer Motion (same)                               |
| CDN Vanta.js + Three.js | `next/script` with `afterInteractive` strategy     |
| Vercel SPA rewrites     | Native Vercel + Next.js                            |
| EmailJS (client)        | API Route (server-side, hides keys) or keep client |
| ESLint (flat config)    | ESLint (flat config — Next.js 16 supports it)      |

### What's New in Next.js 16 That Affects This Migration

| Feature                                   | Impact on Your Portfolio                                      |
| ----------------------------------------- | ------------------------------------------------------------- |
| **Turbopack (stable, default bundler)**   | Replaces Vite's dev server — ~400% faster `next dev` startup  |
| **React Compiler (stable)**               | Auto-memoization — can remove manual `useMemo`/`useCallback`  |
| **`params` is async** (breaking from v15) | `const { slug } = await params` in dynamic routes             |
| **`next build` no longer runs linter**    | Run `npm run lint` separately in CI                           |
| **Turbopack File System Caching**         | Persistent dev cache — even faster restarts                   |
| **Stable Adapter API**                    | Clean Vercel deployment, also supports self-hosting           |
| **AGENTS.md** included by default         | `create-next-app` generates AI agent guidance file            |
| **React 19.2 canary features**            | View Transitions, `useEffectEvent()`, `<Activity/>` available |
| **`use cache` directive**                 | Can cache expensive server operations (optional, advanced)    |

## 3. Key Migration Patterns (Next.js 16 specific)

### 3a. Routing — react-router-dom → Next.js 16

```jsx
// BEFORE (react-router-dom v7)
import { Link, useNavigate, useParams, useLocation } from "react-router-dom";
const navigate = useNavigate();
navigate("/services/web-development");
const { slug } = useParams();

// AFTER (Next.js 16 App Router)
import Link from "next/link"; // same <Link> API
import { useRouter, usePathname } from "next/navigation"; // client only
const router = useRouter();
router.push("/services/web-development");

// ⚠️ BREAKING in Next.js 15+/16: params is a Promise — must await it
// app/services/[slug]/page.jsx
export default async function ServiceDetailPage({ params }) {
  const { slug } = await params; // <-- await required
  // ...
}
```

### 3b. Layout System — Outlet → Nested Layouts


### 3c. Dark Mode — Centralized ThemeProvider (prevents hydration flash)

```jsx
// components/ThemeProvider.jsx
"use client";
import { createContext, useContext, useEffect, useState } from "react";

const ThemeContext = createContext({ dark: false, toggleTheme: () => {} });

export function ThemeProvider({ children }) {
  const [dark, setDark] = useState(false);

  useEffect(() => {
    const stored = localStorage.getItem("theme");
    const prefers = window.matchMedia("(prefers-color-scheme: dark)").matches;
    const initial = stored === "dark" || (!stored && prefers);
    setDark(initial);
    document.documentElement.classList.toggle("dark", initial);
  }, []);

  const toggleTheme = () => {
    setDark((d) => {
      const next = !d;
      document.documentElement.classList.toggle("dark", next);
      localStorage.setItem("theme", next ? "dark" : "light");
      return next;
    });
  };

  return (
    <ThemeContext.Provider value={{ dark, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export const useTheme = () => useContext(ThemeContext);
```

> **Why `suppressHydrationWarning` on `<html>`?** Server renders without `.dark` class, client adds it from localStorage. Without suppression, React warns about the mismatch.

### 3d. ScrollToTop — useLocation → usePathname

```jsx
// BEFORE
import { useLocation } from "react-router-dom";

// AFTER (Next.js 16)
("use client");
import { usePathname } from "next/navigation";
const pathname = usePathname();
// Note: Next.js doesn't expose hash via usePathname — use window.location.hash if needed
```

### 3i. Contact Form — API Route (recommended: hides keys server-side)

```js
// app/api/contact/route.js
import emailjs from "emailjs-com";

export async function POST(request) {
  const body = await request.json();

  // Validate input
  const { name, email, message } = body;
  if (!name || !email || !message) {
    return Response.json({ error: "Missing fields" }, { status: 400 });
  }

  try {
    await emailjs.send(
      process.env.EMAILJS_SERVICE_ID, // server-only env var
      process.env.EMAILJS_TEMPLATE_ID,
      { name, email, message },
      process.env.EMAILJS_PUBLIC_KEY,
    );
    return Response.json({ success: true });
  } catch (err) {
    return Response.json({ error: "Failed to send" }, { status: 500 });
  }
}
```

    ```js
        { url: "https://justankit.dev/terms", lastModified: new Date() },
      ];
    }
    ```
31. Test all routes, dark mode, scroll behavior, Vanta effects
32. Deploy to Vercel — auto-detected as Next.js project

## 5. What You Gain from Migration

| Feature            | Vite SPA (current)                 | Next.js 16                                        |
| ------------------ | ---------------------------------- | ------------------------------------------------- |
| SEO                | Client-rendered, poor crawlability | Server-rendered HTML, per-page metadata           |
| Performance        | Full JS bundle upfront             | Code-split per route, server components = zero JS |
| Static pages       | Still ships React runtime          | Zero JS, pure HTML at build                       |
| Service pages      | Client-side routing only           | Pre-rendered at build via `generateStaticParams`  |
| Dev speed          | Vite (fast)                        | **Turbopack** (~400% faster startup)              |
| Image optimization | Manual                             | `next/image` automatic optimization               |
| Font optimization  | External CDN request               | `next/font` — zero layout shift, self-hosted      |
| 404 handling       | SPA fallback rewrite               | Native `not-found.jsx` with HTTP 404 status       |
| API routes         | None (EmailJS keys exposed)        | Server-side routes (keys hidden)                  |
| Metadata           | Single index.html for all pages    | Per-page dynamic metadata                         |
| Bundler            | Vite + Rollup                      | **Turbopack** (default in Next.js 16)             |
| Auto-memoization   | Manual React.memo/useMemo          | **React Compiler** (stable in Next.js 16)         |

## 6. Potential Pitfalls

1. **Vanta.js + SSR**: Vanta accesses `window` — must be in `'use client'` components. Guard with `typeof window !== 'undefined'` or use `next/dynamic` with `{ ssr: false }`.

2. **Hydration mismatches (dark mode)**: Server renders without `.dark` class. Use `suppressHydrationWarning` on `<html>` and only apply theme in `useEffect` (never during render/SSR).

3. **`params` is async in Next.js 16**: Every dynamic route must `await params`. This is a **breaking change** from Next.js 14 — `const { slug } = await params`.

4. **`next build` doesn't lint anymore**: In Next.js 16, add `npm run lint` as a separate CI step.

5. **Scroll-to-section**: `element.scrollIntoView({ behavior: "smooth" })` works the same. For cross-page (e.g., `/services` → `/#contact`), use `router.push("/#contact")`.

6. **`react-router-dom` complete removal**: Search for all imports from `react-router-dom` — every `Link`, `useNavigate`, `useParams`, `useLocation`, `Outlet` must be replaced.

7. **`import.meta.env` → `process.env`**: Global find-and-replace `import.meta.env.VITE_` → `process.env.NEXT_PUBLIC_`.

8. **Tailwind v3 vs v4**: Next.js 16 defaults to v4 during `create-next-app`. If you want to keep v3, follow the [Tailwind CSS v3 guide](https://nextjs.org/docs/app/guides/tailwind-v3-css) — keep your existing `tailwind.config.js` and `postcss.config.js`.

9. **`Link` import difference**: React Router: `import { Link } from "react-router-dom"` (named export). Next.js: `import Link from "next/link"` (default export). `<Link to=...>` → `<Link href=...>`.

## 8. Quick Reference — Import Replacements

| Before (Vite + react-router-dom)                   | After (Next.js 16)                              |
| -------------------------------------------------- | ----------------------------------------------- |
| `import { Link } from "react-router-dom"`          | `import Link from "next/link"`                  |
| `<Link to="/path">`                                | `<Link href="/path">`                           |
| `import { useNavigate } from "react-router-dom"`   | `import { useRouter } from "next/navigation"`   |
| `navigate("/path")`                                | `router.push("/path")`                          |
| `import { useParams } from "react-router-dom"`     | Use async `params` prop in page component       |
| `const { slug } = useParams()`                     | `const { slug } = await params`                 |
| `import { useLocation } from "react-router-dom"`   | `import { usePathname } from "next/navigation"` |
| `const { pathname } = useLocation()`               | `const pathname = usePathname()`                |
| `import { Outlet } from "react-router-dom"`        | Use `{children}` in layout component            |
| `import { BrowserRouter } from "react-router-dom"` | Delete (Next.js handles routing)                |
| `import.meta.env.VITE_*`                           | `process.env.NEXT_PUBLIC_*`                     |
